# Shell & URL Template-Variable Safety

Rules for escaping untrusted data (card labels, titles — sourced from the GitHub API) before interpolating it into shell commands or URLs via the custom-action template system.

## Rules

- Always escape user-controlled input before interpolating into shell commands. Use `ShellEscape()` / `BuildShellSafeVars()` (POSIX single-quote wrapping: replace `'` with `'\''`, wrap in `'...'`) for every template variable expanded into a shell command. Card labels and titles come from an external API and are not trustworthy — an unescaped label like `"; rm -rf /; "` is arbitrary command execution.
- Two escaping disciplines coexist, and mixing them is a real bug, not a style choice. **Per-variable** escaping (`BuildShellSafeVars` + `ExpandTemplate`) is for a template the *user* wrote — `command:`, `cleanup:` — where each value is substituted into a shell line whose quoting is the user's own; every value arrives pre-quoted. **Whole-token** escaping (`ShellEscape` over the fully expanded string) is for a value *lazyboards itself* places as one argument of a command it assembles — `window:` and `cwd:`, consumed by `action.TmuxNewWindow`/`WithDir` (`internal/action/window.go`, #624). Those two builders take RAW expanded values and escape them; handing them `BuildShellSafeVars` output double-quotes it (`pr-'42'`, `cd ''/some/path''`), which is not a security hole but silently produces the wrong window name or an unusable path. The rule to carry to any new field: if the user writes the command line, escape per variable; if we write it, expand raw and escape the whole token at the boundary.
- A builder that assembles a command line from untrusted values is tested by running the result through a real `sh -c` against a recording stub and asserting the **argv the stub received**, not by comparing the produced string (`internal/action/window_test.go`). A string comparison only proves the output matches whatever the implementation currently emits; an argv assertion proves the shell actually split it into the arguments intended, which is the property that matters when a card title contains `$(...)`, backticks, a quote, or a newline. Pair it with a case that asserts an injected payload never ran (no marker file created).
- For URL query-parameter template variables, always use `url.QueryEscape`, never `url.PathEscape`. `PathEscape` leaves `&`, `=`, `,` unescaped (they're valid path sub-delimiters per RFC 3986), which reopens query-parameter injection — a label like `"bug&extra=malicious"` in `?tags={tags}` becomes `?tags=bug&extra=malicious`. `QueryEscape` correctly encodes all three. Before switching an encoding function (even on reviewer suggestion), verify which characters it actually covers against the RFC 3986 character set rather than trusting the function name's apparent fit.
- Browser opening (`internal/action.DefaultExecutor.OpenURL`) never passes a URL through a shell parser, on any platform. `OpenURL` is the sole chokepoint: it validates with `net/url` (exact `http`/`https` scheme, non-empty hostname) on every platform before dispatching to a per-platform, build-tag-separated `openBrowser` — `ShellExecuteW` on Windows (`golang.org/x/sys/windows`, no `os/exec`), `exec.Command("open"/"xdg-open", url)` on darwin/other, with the URL as a single argv element. Never reintroduce `cmd /c start` or any other shell-mediated launcher — a `type: url` keymap binding from an untrusted repo-local config reaches this sink unstripped (see `docs/trust-model.md`), so it must never be able to inject a second command via `&`, `|`, `^`, `%`, or quotes. The validated URL is handed to the launcher **unmodified** (never `url.URL.String()`) — re-encoding percent-encodes IDN hosts (`https://exämple.de` → an unresolvable `https://ex%C3%A4mple.de`) and would silently change what `xdg-open`/`open` already receive today.
